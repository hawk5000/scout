# Integration readiness

This starter package has no credentials or live resources.

| Dependency | Build behavior before available | Needed for live operation |
|---|---|---|
| Source repository | Build locally; preserve files | User-selected repository and publication authorization |
| SIL access/entitlements | Define adapter; demo explicitly isolated; production denies access | Existing contract, authorized test identity and server-side configuration |
| Model and web research | Fixture-backed provider adapter, no paid calls | Supported model/tool choice, securely configured credentials, approved spend |
| Cloudflare database/jobs | Schema and configuration templates; automated tests | Actual account/resource IDs, approved provisioning/deployment |
| Vercel | Build application and deployment notes | Authorized project and deployment target |
| Update email | In-app update history and disabled notification adapter | Verified sender, authorized recipient and configured provider |
| Pilot properties | Blank hotel template | Actual hotel identity, geography, categories and operator confirmation |

Use current official documentation. Do not invent production URLs, IDs or credentials. Do not display implementation details to hotel customers. Prefer existing services and conventions over adding vendors. No Stripe, PMS, Salesforce connector or voice provider is required for the initial product.
