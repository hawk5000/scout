# Four build passes

## Pass 1 — foundation and interface
Inspect current files and establish the application structure. Implement validated hotel profiles, market boundaries, persistent record contracts, access boundaries, customer navigation, three scout detail views, blueprint table, finding detail, export interface and admin setup. Provide explicit fictional fixtures in demo mode. Implement real search/filter/save/dismiss/copy and CSV export against the demo repository. Keep paid research inactive. Add meaningful tests for access enforcement and exports. Deliver a production-compilable application; live SIL/browser acceptance may remain pending.

## Pass 2 — research engine
Implement provider adapter, three playbooks, schema validation, source evidence, entity matching, version history, meaningful-change detection, bounded retrieval and usage accounting. Test with recorded/synthetic fixtures first. Add live mode only behind authorized configuration and spend limits. Show sources and uncertainty in the UI. Complete failure/partial/no-change states. Never label fixture success as live research validation.

## Pass 3 — subscription delivery
Implement idempotent asynchronous baseline and scheduled cycles, activation/pause controls, bounded retries/checkpoints, update history, configured delivery notifications, per-hotel budgets and actual spend. Integrate verified SIL contracts when available. Keep notification delivery disabled until recipients/provider are configured and authorized. Test concurrent jobs, interrupted runs and duplicate notification prevention.

## Pass 4 — pilot and launch
After explicit authorization and property details, run the initial blueprint and successive updates in Seattle and Portland. Track research quality, duplicate rate, material updates, actual API cost, human correction and onboarding time. Validate deployed responsive UI. Use appropriate verified findings for a labeled public sample. Review commercial assumptions against measured costs. Finish launch pages and production checks without inventing evidence of customer results.

Do not use arbitrary completion percentages. Every pass should end with a concise status update and concrete next dependency.
